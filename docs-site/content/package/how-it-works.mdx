# Как это работает

Ниже - устройство пакета без лишней теории. Если нужно только "поставить и настроить", достаточно разделов [Установка](/docs/package/install) и [Mihomo](/docs/setup/mihomo).

## Блок настроек в nfqws2.conf

При установке или `nfqws-xkeen enable` в начало файла `/opt/etc/nfqws2/nfqws2.conf` добавляется отдельный блок с маркерами `BEGIN` / `END`. Его можно править руками. После изменений перезапустите nfqws2.

| Переменная | Что делает |
|------------|------------|
| `XKEEN_MARK_ONLY` | `1` - в nfqws2 идут только пакеты с меткой mihomo. `0` - обычный режим nfqws2 без этого фильтра. |
| `XKEEN_ROUTE_MARK` | Метка в hex, та же что `routing-mark` в mihomo (`0x10000000` = `268435456`). |
| `XKEEN_ROUTE_MASK` | Маска для iptables. Обычно совпадает с меткой. |

Эти переменные читает штатный скрипт `S51nfqws2` при старте (он делает `. "$CONFFILE"`).

## Что меняется в S51nfqws2

Пакет не отключает firewall nfqws2. Он добавляет небольшой фрагмент в функцию подготовки runtime-конфига:

- если `XKEEN_MARK_ONLY=1`, то в качестве фильтра используется ваша метка mihomo;
- штатный код дальше сам создаёт цепочки `nfqws_post`, `nfqws_pre`, `nfqws_nat` и правила NFQUEUE.

Так сохраняются все тонкости upstream: ответы, NAT, флаги TCP и актуальные порты из конфига nfqws2.

## Бэкапы

Перед правкой файлов копии кладутся в `/opt/var/lib/nfqws-xkeen/`. При снятии интеграции (`uninstall`) патч и блок conf удаляются, а штатное поведение nfqws2 возвращается.

## После обновления nfqws2

Обновление пакета nfqws2 часто перезаписывает `S51nfqws2` "чистым" файлом без нашего фрагмента. Тогда:

```sh
nfqws-xkeen repatch
nfqws-xkeen doctor
```

Блок в `nfqws2.conf` обычно сохраняется (его opkg не затирает так же агрессивно), но init-скрипт нужно пропатчить снова.
